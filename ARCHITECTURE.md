# Лабораторная работа № 8. Адресная книга

Вариант 8 на странице 3 [задания](<Web - Лабораторная работа №8.pdf>) требует CRUD контактов, поиск по имени и телефону, группировку по первой букве, алфавитный указатель, карточки контактов и модальное редактирование. В проект также входят проверка телефона и email, адаптивная вёрстка, схема БД, инструкция по запуску и ревью читаемости, семантики, доступности и производительности.

## Основа проекта

`lab_8` будет самостоятельным приложением на Node.js, Express, SQLite (`better-sqlite3`) и HTML/CSS/JavaScript без сборки. [lab_7](../lab_7/ARCHITECTURE.md) служит ориентиром для структуры сервера, подготовленных SQL-запросов, маршрутов CRUD, валидации и пагинации. Интерфейс строим вокруг сетки карточек. Из [lab_5](../lab_5/css/style.css) берём тёплую палитру, типографику и адаптивную раскладку. README прошлых работ служат образцом для описания аудитории, функций и запуска.

| Слой | Ответственность |
| --- | --- |
| `app.js`, `routes/pages.js`, `middleware/errorHandler.js` | Настройка Express, главная страница, раздача статики, ответы об ошибках |

| `public/index.html`, `public/css/style.css`, `public/js/` | Страница, адаптивные стили, запросы к API, карточки и формы |

## Схема SQLite

```sql
CREATE TABLE IF NOT EXISTS contacts (
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  full_name TEXT NOT NULL,
  phone     TEXT,
  email     TEXT,
  notes     TEXT
);
```

При первом запуске приложение создаёт собственный `lab_8/data/contacts.db` с пустой таблицей `contacts`. Повторный запуск открывает эту же БД и сохраняет записи, добавленные через приложение.

## API

Контакт представлен полями `id`, `full_name`, `phone`, `email`, `notes` в SQLite и JSON. Список дополнительно возвращает данные для алфавитного указателя.

| Метод и путь | Результат |
| --- | --- |
| `GET /api/contacts?q=&page=1&limit=10&letter=А` | `200`, список и метаданные. Все параметры необязательны, без `letter` возвращаются все группы |
| `GET /api/contacts/:id` | `200`, один контакт |
| `POST /api/contacts` | `201`, созданный контакт и заголовок `Location` |
| `PUT /api/contacts/:id` | `200`, обновлённый контакт |
| `DELETE /api/contacts/:id` | `204`, контакт удалён |

Список возвращает `data`, `total`, `page`, `limit`, `totalPages` и `letters` с доступными группами. В каждом элементе `data` есть `initial` для заголовка группы. `letters` учитывает поиск `q` по всему результату. `total` и `totalPages` учитывают также выбранную букву. Это позволяет переключать группу даже на странице, где видны только контакты под одной буквой.

Форма передаёт `full_name`, `phone`, `email`, `notes`. Имя обязательно, после удаления пробелов по краям допускается до 100 символов. Email проверяем по формату из `lab_7`, телефон допускает цифры, пробелы, `+`, скобки и дефисы и должен содержать хотя бы одну цифру. Заметки необязательны, до 1000 символов. `PUT` заменяет редактируемые поля контакта. Пустые и пропущенные необязательные поля храним как `NULL`. Ошибки параметров или формы дают `400`, отсутствующий контакт даёт `404`, сбой сервера даёт `500`.

## Поиск, алфавит и пагинация

1. Сервер получает контакты из SQLite. В модуле списка ищем по подстроке имени без учёта регистра, включая кириллицу, и по номеру без пробелов, скобок и дефисов.
2. Определяем первую букву по имени после удаления начальных пробелов и нормализации Unicode. Порядок групп фиксируем: русские `А–Я` с `Ё` после `Е`, затем латинские `A–Z`, затем `#` для остальных символов. Внутри группы сравниваем имена через `Intl.Collator('ru')`, при равенстве сравниваем `id`.
3. Из результатов поиска формируем список доступных букв. Затем применяем выбранную букву и берём срез для нужной страницы. Новый поисковый запрос показывает все совпавшие буквы с первой страницы. Смена буквы также возвращает на первую страницу. После удаления или редактирования клиент переходит на последнюю доступную страницу текущей выборки, а если её буква исчезла из указателя, выбирает «Все».

Для небольшого учебного справочника поиск и сортировка в Node.js позволяют применить одни правила к карточкам и указателю. На каждый запрос списка сервер читает таблицу целиком, поэтому время и память зависят от числа контактов. Проверим это в рамках ревью на наборе, который занимает несколько страниц.

## Интерфейс

- Главная страница показывает поиск, кнопку «Добавить контакт», алфавитный указатель «Все» и доступные буквы. Карточки идут под буквенными заголовками. В них видны имя, телефон, email и заметки.
- Один нативный `<dialog>` обслуживает добавление и редактирование. Поля имеют видимые подписи и сообщения о неверных значениях. После закрытия фокус возвращается к кнопке, открывшей форму, либо к «Добавить контакт», если карточка исчезла из выборки. Удаление выполняется после подтверждения.
- На узком экране отображается одна колонка, на широком сетка расширяется. Указатель переносится по строкам, выбранную букву отмечаем через `aria-pressed`. Предусматриваем состояния загрузки, пустого списка и ошибки. Текст контактов вставляется через `textContent`.
